# ReportDesk · 报表管理

当前 Electron 0.2.0 首次导入外部报表目录或 XML 后自动记住来源路径，后续启动自动读取；点击「连接并保存」成功后自动保存配置，默认以当前 Windows 用户 DPAPI 加密保存密码，可取消勾选。无收藏、最近、分类和说明编辑；不保存查询参数或结果，旧 catalog 保留原样。详见 [持久化行为与验证](docs/Verification-Persistence-20260914.md)。下文涉及 catalog、收藏及分类的操作属于保留的 WinForms 0.1.4 基线。

报表内容分类、无 SQL 定义单列和外部位置配置见 [ReportLocations](docs/ReportLocations.md)。

本机测试使用 `E:\his\LIB` 和本机 Oracle ORCL。SQL 保存测试使用隔离副本，凭据仅在内存读取；命令与验证边界见 [本机测试说明](docs/LocalTesting.md)。

**Electron 桌面开发版**：已新增 Windows 10/11 x64 界面，采用统一浅色底面、暖灰与香槟金点缀，保留原有圆角进度条风格，左侧报表直接切换查询区、横排条件、执行进度与取消。构建、使用和验收边界见 [Desktop.md](docs/Desktop.md)。下文记录的是保留用于回归的 WinForms 0.1.4；Electron 版不再以 x86/旧系统为本轮目标。

第一版 Windows 桌面程序：导入 HIS 查询设置 XML，按名称/别名/说明/来源搜索，分类、收藏、最近使用，生成条件表单，执行 Oracle 查询，以统一表格展示并导出 `.xlsx`。不依赖 FS/FarPoint，不复刻原报表打印版式。

Electron 版支持选择 **报表根目录**，递归识别查询定义并检查配套 XML；在「报表说明 → 检查关联 XML」查看匹配依据。匹配文件不会自动消除未支持的交叉/映射规则。相同运行时和依赖的文件夹版可使用三文件离线更新包，无需每次复制完整 Electron，详见 [OfflineUpdate.md](docs/OfflineUpdate.md)。

已适配的表格查询会在更新后重新导入生效；支持原明细 SQL 的中文参数绑定。

## 使用

1. Windows 10 电脑安装 **.NET Framework 4.8 或更高版本**。本版以 Win10 1607 及以上作为运行前提；更早系统未覆盖。32 位系统使用 `win-x86` 包，64 位系统优先使用 `win-x64` 包。
2. 解压整个程序包到一个独立文件夹，双击 `ReportDesk.exe`。**不要只复制 exe**；随包 DLL 必须保留。不需要安装原 HIS 报表组件。
3. 点击「体验演示」可离线体验日期条件、查询、结果筛选、排序和导出。数据明确标为模拟，完全不连接数据库。
4. 点击「导入文件夹」选内网报表 XML 所在目录，或单独「导入 XML」。只读取 `ReportQueryInfo` 定义，跳过其他模板与配置；成功、待适配、失败数会显示在状态栏。原 XML 保持不变。
5. 打开「连接设置 → 常规」，可填写连接名。连接类型选择「基本」时填写主机、端口、服务名（Service Name）；选择「TNS」时从「网络服务名」选择已有别名，再填写只读用户名和密码。没有服务列表时点击「配置网络服务来源」进入高级页选择 `tnsnames.ora`。点击「测试连接」验证登录连通性，点击「确定」保存设置。默认不保存密码；勾选后用 Windows CurrentUser DPAPI 加密保存在本机用户目录。
6. 选择「可试查 · 未核对」报表，选择数据源，填查询条件。下拉框先点「加载选项」，再选择值。`全部` 只有原定义提供时才出现，且不自动选中。
7. 对当前科室/操作员/明细项目等隐含参数，填写已确认的对应编码。不能填姓名代替 ID，也不能删除原科室限制。
8. 点击「查询」。结果列标题可排序，「结果内查找」是已加载数据的文字筛选。支持多行复制与「导出 Excel」。主表/明细/合计 SQL 分别选择执行；不会自动去掉过滤条件或合并结果。
9. 与 HIS 相同条件核对后，可在「说明」中记录口径、分类、别名并标记用户已核对。若原文件内容变更并重新导入，验证状态自动重置，备注和收藏保留。

## 范围与限制

- **0.1.4 手工配置报表显示**：在 `ReportDesk.exe` 同目录放置 `report-visibility.xml`，按报表 ID 列出该岗位电脑需要显示的报表，重启生效。无前端岗位配置或切换入口。搜索、分类、收藏、最近使用、待适配和演示遵循同一清单；未列出的新导入报表保持隐藏。缺少配置文件兼容旧版显示全部，selected 空清单显示零张，错误配置停止启动。操作步骤及样例见 [ReportVisibility.md](docs/ReportVisibility.md)（程序包中位于同目录）。这是本地显示配置，不是登录或数据库权限控制。

- **0.1.3 取消程序的时间与结果上限**：Oracle 命令 CommandTimeout=0，移除查询计时取消、5000/50000 行限制与 32 MiB 截断。直接连接不再附加 CONNECT_TIMEOUT、TRANSPORT_CONNECT_TIMEOUT 或 RETRY_COUNT，ConnectionTimeout=0 且不启用连接池。旧目录中的 TimeoutSeconds/MaxRows 仅为兼容保留，运行时忽略；高级页已去掉可设置的限额。
- “程序不限制”不等于连接永不超时：TNS 文件原有超时、驱动默认行为、操作系统、监听器及数据库端设置仍可能终止连接/查询，本程序不修改它们。手动取消保留，连接握手期间不保证立即响应。结果仍加载在内存中，大结果集可能耗尽内存，尤其是 x86；失败会报错，不把部分数据当作成功完整结果。

- 连接窗口按常规/高级分组：常规提供连接名、基本/TNS、网络服务名、用户名、密码；高级提供 TNS 来源、刷新服务和当前运行规则说明。连接名仅是当前一组设置的备注名，本版不增加多连接管理、SSH 或数据库管理功能。
- 未保存 TNS 文件路径时，自动查找环境变量 `TNS_ADMIN`、`ORACLE_HOME/network/admin`、程序目录及其 `network/admin`，以及 Windows Oracle 注册表 32/64 位视图中的对应路径。只检查这些位置的 `tnsnames.ora`，不扫描磁盘或读取 Navicat 账号配置。发现唯一文件才自动加载，多文件时在高级页选择来源；网络服务名仍由用户选择。保存路径失效时明确报错，不自动切换其他数据库来源。
- 「测试连接」使用当前输入登录数据库、读取驱动提供的服务器版本并关闭非池化连接，不执行报表 SQL，不保存本次输入，不变更数据库对象/权限。数据库可能产生正常登录审计；无需数据库备份或数据回滚。实际联网测试由用户在内网点击执行，开发验证不联网。
- 测试成功只表示登录连通，不证明报表权限或只读权限正确。测试时禁止重复点击或编辑；修改连接输入后清除旧成功提示。握手仍遵循原配置超时，关闭窗口不能立即中断握手，后台测试在握手返回后释放连接。

- **0.1.1 新增 TNS 文件连接**：保留文件中所选别名的连接描述（除注释外），交给 Oracle 驱动处理；支持提取 `DESCRIPTION`、`DESCRIPTION_LIST`、多地址、`SERVICE_NAME` 和 `SID`，实际网络行为仍须在内网验收。直接连接方式仍使用 Service Name。
- TNS 文件只读，每次查询/加载下拉选项前重新读取。只保存文件路径和别名，不保存描述副本、不修改系统 `TNS_ADMIN` 或 HIS 配置；文件移动、别名删除或重名会报错，不回退到其他全局别名。切换连接方式保留已填写的服务器设置。
- TNS 文件不超过 1 MiB，支持 `#` 注释、多行、简单单/双引号值和逗号分隔别名；别名限字母、数字、下划线、点、短横线。支持带 BOM 的 UTF-8/UTF-16；无 BOM 时按 Windows 当前代码页读取。使用 ASCII 网络地址最稳妥。
- 暂不展开 `IFILE`；若文件使用它，请直接选择包含实际别名定义的文件。不自动加载相邻 `sqlnet.ora`、LDAP、钱包或外部认证；不是完整 Oracle 客户端配置迁移。连接描述中的其他参数由驱动验证，不承诺所有 Oracle Net 语法都已适配。
- TNS 握手超时、重试次数和多地址等待遵循连接描述/驱动规则。文件内已有的 `CONNECT_TIMEOUT`、`TRANSPORT_CONNECT_TIMEOUT` 和 `RETRY_COUNT` 保持原样。

- XML 结构可解析不等于 Oracle 能执行，更不等于口径已验证。当前静态适配状态只是试查资格。
- **仅呈现所选 SQL 数据源的原始结果**。不自动生成模板合计、交叉表、映射行列、打印分组。多个数据源分次执行，不保证跨查询同一快照。
- 已支持日期、文本、SQL 提供的单选下拉框、明确的 LIKE/左补齐参数。字典引用、自定义/树/复选控件、交叉数据、映射数据及条件数据源需后续适配；存在这些依赖的报表保留目录但禁用查询。
- SQL 参数使用绑定，不复制用户输入进 SQL 文本。保守拒绝多语句、写操作、动态标识符、原生 `:bind`、Q/N 引用字符串、数据库链接、全角括号等未支持形式。误拦截时应适配定义，不关闭保护。
- `&CurrentDeptID` 等不自动模拟 HIS 登录状态。工具不知道登录角色可访问哪些科室；上线前必须核实账号权限和数据范围。
- 连接打开阶段通过网络连接超时限制，取消不保证立即中断连接握手。执行和读取阶段会请求 Oracle 取消；服务端真正停止仍需内网验证。
- 不做数据库全量导出。Excel 导出的是当前筛选/排序后的已加载表格；不会重新查询。字符串作为文本，前导零保留，长数字文本化，日期以 ISO 文本保存；超过 Excel 单元格限制会明确失败而不截断数据。
- 暂不展示 LOB/二进制/特殊 Oracle 类型；遇到未支持类型停止查询并提示，不静默丢字段。
- 查询不限制行数，但 `.xlsx` 单工作表的物理容量仍为 1,048,576 行（含标题）/16,384 列；超过容量明确拒绝导出，不静默截断。本版未增加跨工作表拆分。

## 错误日志

- 点击主窗口「打开日志」，或在资源管理器地址栏输入 `%LOCALAPPDATA%\ReportDesk\logs`。有错误时生成当天的 `ReportDesk-yyyy-MM-dd.log`，按天追加，不自动删除历史日志；尚无错误时目录可能为空。
- 日志记录时间（含时区）、版本、x86/x64、失败操作、异常类型、HResult、Oracle 错误码、过滤后的消息、内部异常及方法调用栈。覆盖连接测试、查询、导入失败、配置、导出/主窗口操作、表格显示、启动及未捕获异常。
- 不写密码、完整连接串、SQL 正文、参数值或结果快照。已知凭据及输入值、SQL/连接描述、引用内容会过滤；未知上下文的未捕获异常/表格数据错误只记类型、错误码和调用栈，不写原始消息。日志不是无过滤的 Exception.ToString 输出。
- 日志写入失败会在错误提示中说明目录权限/磁盘空间问题，不冒充写入成功，也不覆盖原有故障。日常手动取消不记作错误；取消请求自身报错会记录。
- 向他人提供日志前可先查看内容。日志不自动上传；更新/回退程序不会自动删除日志。

## 数据与影响范围

- 程序新增本地文件；不改变 HIS、原 XML、数据库 schema 或权限。查询在非池化连接的只读事务内运行，连接关闭后回滚该事务。
- **数据库最小权限仍是边界**：SQL 检查和只读事务不能代替只读账号，也不能保证具有自治事务或外部副作用的数据库函数安全。现场应审核账号可执行函数/过程、查询对象和科室范围。
- 不连接任何数据库进行开发验收；真实环境验证由用户在内网执行。
- 用户目录：`%LOCALAPPDATA%\ReportDesk\catalog.json`，保存定义、来源、分类、收藏、备注、验证状态、最后使用时间和连接设置。备份为 `catalog.json.bak`。不保存查询结果和查询参数值，不写 SQL 执行日志。
- 密码加密仅适用于同一 Windows 用户/机器，换机器后重新输入。未保存密码只在当前进程内使用。连接设置不是系统密码管理器。
- 更新前可备份整个 `%LOCALAPPDATA%\ReportDesk`；新程序解压到新目录即可。0.1.3 兼容旧版目录，原连接方式和密码保存选择保持，旧时间/行数限额不再生效。需回退时关闭新版本，恢复更新前的目录备份后打开旧版本（旧版可能不接受新版保存的零限额；0.1.0 不识别 TNS）。本版不提供自动升级。
- 报表库损坏时不会覆盖为空库。关闭程序后先备份故障文件，再按需要恢复 `.bak`。
- 程序包不包含原 HIS 资料或真实数据，只包含自建程序及运行依赖。批量资料通过应用导入，不自动迁移知识库。

## 构建与验证

在项目根目录使用 PowerShell（需要可还原 NuGet 的 .NET SDK）：

```powershell
powershell -File scripts/build.ps1
```

该命令生成 x86/x64 两包、运行独立检查程序和 WinForms 离线冒烟检查。产物：`artifacts/packages`；本版证据：`artifacts/verification/0.1.4`。任一步失败会停止，不声称 Win10 或 Oracle 验收通过。UI 中测试连接的成功/失败使用注入的模拟结果，自动发现使用合成目录，不读取本机真实 Oracle 配置。模拟错误日志写入隔离的验证目录。岗位显示检查使用隔离报表库和配置文件，覆盖同名 ID、各导航入口、新导入、演示、模拟查询/导出、空清单、重启和错误配置。

可选外部定义目录只读扫描：

```powershell
powershell -File scripts/build.ps1 -ScanDirectory '<外部报表定义目录>'
```

离线检查涵盖参数转义/绑定、危险及不支持语法拒绝、编码、XXE、同名来源、更新状态重置、目录备份、DPAPI、导出原子性/编号/精度/公式字符串、模拟数据筛选。UI 检查运行模拟查询、搜索、收藏、结果筛选、排序、导出并保存界面截图。

**Windows 11 x64 上跑通 x86 进程，不等于在 Windows 10 32 位系统验收通过。** 真实系统矩阵见随包 `Acceptance.md`。

## 技术依据

- C# / WinForms / .NET Framework 4.8，Oracle.ManagedDataAccess **19.32.0**；不采用仅支持 x64 的当前新版驱动。
- [Oracle 19c ODP.NET 系统要求](https://docs.oracle.com/en/database/oracle/oracle-database/19/odpnt/InstallSystemRequirements.html)
- [Oracle 19.32.0 NuGet](https://www.nuget.org/packages/Oracle.ManagedDataAccess/19.32.0)
- [Oracle 19c 连接描述与 TNS 别名](https://docs.oracle.com/en/database/oracle/oracle-database/19/odpnt/featConnecting.html)：本程序从显式选择的文件提取描述作为 Data Source，避免全局别名缓存混用。
- [OracleConnection.Open](https://docs.oracle.com/en/database/oracle/oracle-database/19/odpnt/ConnectionOpen.html)：用于用户主动点击的登录连通性测试。
- [Oracle CommandTimeout](https://docs.oracle.com/en/database/oracle/oracle-database/19/odpnt/CommandCommandTimeout.html)：0 表示不限制命令执行时间。
- [Oracle ConnectionString](https://docs.oracle.com/en/database/oracle/oracle-database/19/odpnt/ConnectionConnectionString.html)：Connection Timeout 主要控制连接池等待，不能视为新建网络连接的无限等待保证。
- [.NET Framework 系统要求](https://learn.microsoft.com/en-us/dotnet/framework/get-started/system-requirements)

第一次内网试查建议先选短时间范围、少量数据、口径明确的报表；不要从全院大范围日报开始。
