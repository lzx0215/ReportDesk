# 待适配处理与重新检查

本轮针对 Electron 0.2.0 x64。HIS 原安装目录和知识库只读，不连接真实 Oracle，不执行 HIS DLL，不修改数据库配置、权限或业务 SQL 过滤范围。

## 用户操作

关闭 ReportDesk，备份三个运行文件及 `%LOCALAPPDATA%\ReportDesk\catalog.json`。将更新包 `payload` 内部的 `resources` 合并到程序目录，成套替换 app.asar、ReportDesk.Host.exe、ReportDesk.Core.dll。原 Electron 和 Oracle 驱动保持不变。

启动后点击左侧 **↻（重新检查适配）**。程序读取已导入且允许显示的报表原 XML，重新生成适配判断并保存；不用重复扫描整个 HIS。路径不可用、XML 损坏或已非查询定义时，明确列出未更新项并保留旧条目，不将其当作检查通过。取消不保存半批结果。原文件已变成无 SQL 定义时更新并从独立列表隐藏。

保持收藏、别名、备注和手工分类。原文件哈希或导入后的 SQL 改变会取消原核对标记；仍需内网核对。此功能需要原路径可读；换路径时使用导入入口。

回退时恢复三个运行文件，并恢复升级前 catalog，或用旧程序重新导入后再查询。新增加的可选字段记录数据源级检查，不保存查询参数和结果；旧 catalog 在重新检查前仍按原整表拦截处理。WinForms 保留用于回归，本轮新增按钮和独立数据源放行交付在 Electron 界面。

## 实际改动

- 多语句、原生冒号参数、数据库链接、中文括号分别提示原因及 SQL 行列；坐标基于移除 SQL 首尾空白后的“查看 SQL”对应查询内容，不是 XML 文件行号。不在报错中输出整段 SQL 或用户值。
- “(病案)危重抢救患者明细”精确源哈希 `8b6b85cf2f899fccc5002a41fd33fae560f84256c9d0fe356867dcff29c2356c` 的导入副本，仅修正 `wm_concat（类型)` 为 `wm_concat(类型)`。界面明确说明，原 XML 不动；其他版本仍按实际问题拦截。未验证现场 wm_concat 函数及结果。
- 无跨数据源依赖时，单个查询的 SQL 语法错误只阻塞该数据源。来源下拉框标注待适配，切换到独立可执行数据源后可试查；后台也独立校验，不能靠界面绕过。
- 共享参数控件、交叉、行分组、用途/顺序、属性依赖仍整体拦截。未扩大为对任意复杂明细的自动拆分。
- 全库仍有 1284 张独立报表：945 张全部数据源通过检查；17 张部分数据源可试查；322 张全部阻塞。339 张仍含待适配项。版式/其他/不完整定义排除规则不变。全库审计：`artifacts/audit/his-recheck-20260911/audit.json`。

## 验证

本机 x86/x64 各 96 项检查通过（包括原真实 XML 样本），WinForms 构建启动检查通过。新增检查覆盖四种 SQL 提示、引号和注释保护、独立数据源放行、共享依赖拦截、旧 catalog 保守行为、序列化、取消、源文件缺失、收藏备注保留。

`tests/desktop/recheck-checks.cjs` 验证旧版本导入 → 新版重新检查 → 真实 Electron 按钮刷新，并核对原文件哈希、未知版本仍阻塞、动态切换数据源以及原 10px 进度条。主后台分页/全量导出/取消/DPAPI/显示过滤回归通过。打包更新验证结果见本轮交付记录。

真实 Oracle、HIS 同条件结果对比、Windows 10 现场环境：**NOT RUN**。本轮不是全部 HIS 引擎功能完成。
