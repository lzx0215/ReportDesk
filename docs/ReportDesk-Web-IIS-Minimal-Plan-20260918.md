# ReportDesk 内网 Web 简化技术方案

日期：2026-09-18。版本：v1.1 评审稿。按用户最新要求：仅内网、人数不多，优先简单、可用、好维护。本稿取代上一版的架构及实施安排，不代表已经开发或部署。

## 1. 就做这些

- 一个 IIS 网站、一个应用池，普通网页免登录。
- 现有查询页面做浏览器适配，不重新设计整套页面。
- 同一网站下提供受限 `/admin` 维护页：连接设置、导入、SQL 编辑、报表列同步和同步状态。
- 服务器保留一份固定路径的报表工作目录；初次从完整 LIB 导入，以后自动读取 HIS 已发布更新，不用启动 HIP。
- 保留桌面客户端和现有报表处理规则，不为 Web 改变 SQL 业务口径。

不默认做：双站点、多进程服务拆分、账号/岗位管理平台、审批流程、草稿发布系统、长期报表版本库、Redis、新业务数据库、独立 Windows 服务、50 人容量工程。

上一版把“以后可能需要”的隔离和版本管理提前变成首版要求，不适合当前规模。此次简化架构和部署，不删除已有查询、编辑功能，也不省掉防止串数据、误覆盖的基本检查。

## 2. 最小改造方式

代码基线仍为当前本地 `main / e54c88f / Electron 0.3.0`。本次重新核对 `Directory.Build.props` 和 Core 项目：现有目标是 `net48`，Oracle 依赖是 `Oracle.ManagedDataAccess 19.32.0`。

| 部分 | 简化后的做法 |
| --- | --- |
| 服务器程序 | 优先新增一个 `ReportDesk.Web`，用 ASP.NET / .NET Framework 4.8 托管于 IIS；先验证与现有 Core 可直接集成，不默认迁移 .NET 10 |
| 业务代码 | 直接引用 Core；仅抽取 Host 中实际需要的调用逻辑，不要求先建 Application、Server 等多个新项目 |
| 前端 | 沿用 HTML/CSS/JS、条件弹窗和 SQL 编辑器；Electron 调用替换为 HTTP，文件导出变成浏览器下载 |
| 页面 | 查询工作台、维护设置页、SQL/列同步编辑页；同步状态放在维护设置中，不另建运维平台 |
| 数据 | 一份服务器报表目录、一份连接配置、一份同步状态文件和脱敏日志；数据放在网站静态目录之外 |
| 自动更新 | 网站内一个后台同步任务；IIS 启动时补查，运行时周期检查，不依赖有人访问页面 |
| 更新程序 | 交付一份完整 Web 发布包；桌面原有打包方式不变 |

不直接将 Electron EXE 放到 IIS，也不把 Host 的全局 result/lookup 当作所有人的共享状态。

ASP.NET 4.x 路线仍需核实服务器 .NET Framework 4.8 和 IIS ASP.NET 功能。此前“PATH 没有 dotnet”不能用来判断 Framework 4.8 是否安装；本路线不以安装 ASP.NET Core Hosting Bundle 为前提。若最小集成验证确有阻塞，再说明具体问题，不静默扩大改造。

### HTTP 只承担必要调用

| 接口范围（拟定） | 内容 |
| --- | --- |
| `/api/reports` | 列表、选择、条件定义和说明；不回传完整 SQL、密码或服务器绝对路径 |
| `/api/query`、`/api/tasks` | 查询、状态、取消、结果分页/排序/筛选、清理；任务归属校验 |
| `/api/lookup`、`/api/export` | 选项加载/搜索/多选、本人完整结果下载；不重新执行查询来导出 |
| `/api/admin/*` | 导入/重载、连接/TNS、SQL 检查/保存、列同步、日志、立即同步；统一限制访问 |

维护试查使用同一套查询组件，不另做第二套查询引擎。复制、草稿提示等纯界面操作不设计额外 API。具体字段沿用现有 DTO 所需内容，不提供转发任意 Host 方法的通用接口。

## 4. 不启动 HIP 的自动同步

交接静态证据表明：其他电脑发布后，压缩报表内容写入 `SYS_UPDATE_RELEASE` / `SYS_UPDATE_RELEASE_FILE`，HIP 启动时读取并更新文件。新功能只实现这段读取逻辑，不运行 HIP、不写 HIS 发布表。

流程：定期检查已发布记录 → 下载报表及配套文件 → 暂存解压校验 → 更新服务器工作目录 → 重载受影响报表。

- 初次用完整 LIB 建立基线；初始导入和之后启动都补查发布，避免只记录“最新编号”而漏过导入期间的更新。
- 检查间隔先建议 30 秒，可配置；这不是保证发布后 30 秒内一定完成更新。
- 只读取发布表，只接收识别的报表/必要配套文件；拒绝路径越界、损坏压缩包，不执行 DLL/EXE。
- 同步状态文件只记录发布/文件标识、成功文件哈希和待重试项；重叠回查并定期复核，不能只按最大编号或最大时间跳过晚提交。
- 查询 XML 和模板同批检查、同批处理；短时间锁住相关报表的重载/新查询准备，不让查询读到一半新一半旧的定义。已经执行的查询使用原定义完成。
- 同步失败保留或恢复上一份可用文件并提示，不能把半更新标为成功。采用本批临时恢复副本和未完成标记；启动时先处理未完成批次，再开放受影响报表。只为故障恢复，不建长期版本库。
- 网页编辑和同步共用报表写锁。文件相对上次同步已被网页/外部修改时，暂停覆盖该报表并提示冲突；仅提供明确的接受 HIS 版/暂保留本地操作，不自动合并 SQL。未确认前保持本地文件。
- 页面只显示“最后成功同步、失败/冲突说明、立即检查”，不做复杂版本中心。

网页 SQL/模板编辑：保存即尝试重载本程序使用的文件，不增加审批或“启用版本”步骤；不等于发布回 HIS。双 XML 保存沿用现有检查，并纳入上述未完成批次恢复保护，不宣称两个文件本身具备原子替换能力。

网站正常运行时自动同步。配置 IIS 预加载/常驻并验证无人访问时仍运行；后台任务接入应用生命周期，避免随意启动一个不受管理的线程。应用池仅一个工作进程，重启交接期间仍以跨进程锁防两个同步者同时写。IIS 停止则同步暂停，重新启动后补查；不承诺独立服务级别的持续运行，也不因此自动新增 Windows 服务。

## 5. 小规模也必须保留的底线

1. **不串结果**：每个浏览器会话、标签页任务独立；分页、取消、选项、下载校验所属会话。结果仅内存保存，不保存患者结果/参数到磁盘；页面刷新尽力恢复当前内存任务，应用回收后明确提示重查，不自动重跑。
2. **维护入口受限**：查询仍免登录。简化建议是指定维护电脑 IP 白名单，同时约束 `/admin` 和 `/api/admin/*`，不是只隐藏按钮。具体名单上线前确认，未配置时维护入口拒绝访问；不擅自开放整个内网。IP 限制不是实名登录；若现场已有可用 Windows 认证，可复用，但不建设新账号系统。
3. **限制落实在服务器**：IP 由可信连接信息取得，不相信客户端自报地址；代理场景先核对真实来源。保留 CSRF/同源检查，防止已允许的维护电脑被跨站诱导写入。密码只写不回显，敏感响应不缓存，日志不记录 SQL、参数、密码和结果；使用院内 HTTPS。
4. **保持现有执行规则**：绑定参数、现场最小权限 Oracle 账号、无固定应用查询超时、不静默截断结果；人数少不等于单个报表不会很大。仅做简单可配置的并发准入，忙时提示等待/稍后重试，不建独立队列系统。结果清理时机在实现时明确告知，不暗加行数/内存截断。
5. **文件与配置保护**：仅访问配置根下的文件，不提供任意磁盘浏览。配置与报表位于网站之外，应用身份仅获必要权限。密码记忆可沿用服务账号 CurrentUser DPAPI，先验证应用池配置文件和重启后解密；不复用开发电脑密文、不回退明文。取消记忆只保存在进程内，重启需重新输入；不需要跨站点密钥传递系统。

单站点这里提供的是路由/访问控制隔离，不宣称查询与维护有进程级安全隔离。IIS 本身支持 IP 白名单，具体功能安装和路径配置需现场验收：[微软 IP 限制说明](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/security/ipsecurity/)。

固定工作目录使当前路径型报表 ID 可继续沿用，不默认另建 ID 注册系统；搬动目录后重新导入并核对位置关联。每次加载记录文件哈希，用于保存冲突和查询定义变更提示即可，不设计完整版本仓库。

## 6. 实施和验收只分三步

| 步骤 | 完成标准 |
| --- | --- |
| 1. 查询网页版 | 最小 net48/IIS 集成通过；原查询、条件、字典、筛选排序、复制、导出、取消可用；两台电脑和同浏览器双标签不串数据 |
| 2. 网页维护 | 导入/连接/TNS、SQL 编辑、列同步完整迁移；特别测试 SQL 先保存再补模板；非允许电脑直接访问维护接口被拒绝 |
| 3. 自动同步与交付 | 授权环境用既有发布样本完成解压比对，再验证发布后自动更新；断网恢复、冲突不覆盖、中途失败恢复和 IIS 重启补查通过；交付一个网站包和短部署说明 |

功能完成按第 3 节逐项勾选，不用“首页打开了”替代完成。先用实际少量使用者和代表性报表验收，不再把 50 会话压测作为首版门槛。发现真实容量问题后再针对性调整。

部署不占用已有 80/8080/8081 绑定，不改既有网站；服务器路径按实际磁盘确定。安装/升级前备份目标站点配置、当前程序和将变动的报表/配置，维护窗口内替换；程序回退与报表恢复分开，不回写 HIS 数据。服务器重启/应用回收可能中断任务，需要如实提示。

上线前只需落实：服务器固定报表路径、访问地址及维护电脑范围、Oracle 查询和发布表的批准只读权限。具体端口、凭据及保留清理参数留在部署配置，不在方案中猜测或填生产秘密。
