# Web LIB 目录与发布同步增量验证

2026-09-20 补充：此处全库业务桥接通过不代表同步基线初始化通过。完整启动后来复现并修复旧模板 XML 校验阻断，见 [完整 LIB 启动修复](Verification-Web-LibStartup-20260920.md)。以下保留当时验证范围。

本次新包面向现有 net462 IIS 站点，默认 `ReportDesk.ReportsDirectory=C:\LIB`。连接配置、日志仍位于 `ReportDesk.DataDirectory`，默认 `C:\ReportDeskData`。桌面版不改动。

## 行为与边界

- 显式报表目录必须已存在且不与网站、配置、日志、同步状态重叠；缺少新配置时兼容旧版 `DataDirectory\Reports`。
- 启动及检查新增扫描完整配置根目录，保留旧来源记录但不加载根外记录。无需浏览器上传整个 LIB。
- 切换报表根目录隔离同步状态，避免复用另一目录的基线或恢复日志。直接读取意味着 SQL 编辑、模板保存、上传和已启用的发布同步会写 `C:\LIB`，应事先备份，禁止其他下载程序同时写该目录。
- 现有后台从 Oracle 发布表轮询、下载、校验和重载的逻辑保留。新包不擅自启用连接或确认发布样本；同步状态分别显示 Offline、SyncEnabled、SyncSampleValidated 的阻塞原因。
- 新增仅返回版本的已认证 GET 接口；可见网页空闲时每 10 秒检查目录版本，更新列表不清空结果、不重新选择报表、不重跑 SQL，弹窗打开时推迟。新查询仍受定义 hash 检查保护。
- 下载默认每轮完成后等待 30 秒；耗时、繁忙等待及失败重试另计。需要 IIS 常驻、预加载、已保存的可解密连接、发布表权限及真实发布样本验证，不能宣称固定秒数内必定同步。

## 服务器替换与验收

1. 备份当前网站、Web.config、`C:\LIB` 和 `C:\ReportDeskData`；只停止本程序 `ReportWeb` 应用池，执行中的任务会中断。
2. 解压完整 net462 新包到新网站目录，保留新包的 DLL、UI、依赖绑定及 Framework 配置。将旧 ReportDesk.* 现场参数逐项迁入，保留 `ReportsDirectory=C:\LIB`。不要覆盖成旧 Web.config，不移动旧连接密文到其他服务身份。
3. 确认应用池对 LIB 和数据目录的必要读写权限，切换本站物理路径并启动。首先确认页面显示的来源为 `C:\LIB`、报表目录正确。
4. 真实发布样本核对通过后，配置 `Offline=false`、`SyncEnabled=true`、`SyncSampleValidated=true`。先用“同步状态 → 立即检查”确认成功，再验证后台下载。不能为了消除提示而跳过样本核对。
5. 配置并验收 IIS Application Initialization、AlwaysRunning、preloadEnabled 和空闲超时为 0。关闭所有浏览器后由另一主机发布已获准的完整报表，核对服务器 LIB 文件及状态，再打开网页确认新定义。保持打开的其他网页应在下一次空闲检查后看到更新提示；重新选择后再查询。
6. 失败时只停止本程序池并切回旧 net462 网站；程序回退不会撤销 LIB 改动，必要时另行恢复 LIB 和对应数据目录备份，不回滚 HIS 数据库。
