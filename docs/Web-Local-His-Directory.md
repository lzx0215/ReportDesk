# Web 本机 HIS 目录维护

本功能只扩展网页版。在左侧文件夹 **报表来源 → 打开本机目录** 中选择本机目录和备份目录；数据库连接在齿轮设置中。`ReportDesk.ServerReportsEnabled` 未配置时默认为 `false`，启动不扫描、不依赖服务器 LIB；只有显式设为 `true` 才显示服务器导入及 HIS 发布同步。目录操作不读取、保存或测试数据库连接，切换来源页签也不会改变实际使用的目录。

## 使用范围

- 每个浏览器页面选择自己电脑上的报表目录，SQL 或 XML 保存回所选目录。
- 所选目录下的全部 `.xml` 会按原始字节上传到服务器的独立临时工作区；不会写入服务器公共报表目录。建议选择包含查询和配套模板的报表子目录。
- 数据库查询仍由服务器执行，使用原有数据库连接。这不是让浏览器直连 Oracle，也不会自动读取本机 TNS。
- 原有维护入口、维护 IP 白名单、CSRF 和同源检查继续生效。本功能不会将普通查询用户提升为维护用户。
- 本机模式不使用服务器的导入、同步、发布功能。默认模式关闭本机目录后显示空列表，等待重新选择；仅服务器兼容模式支持明确切回服务器报表目录。

## 首次操作：只用目录副本

1. 先将需要维护的 HIS 报表目录复制到一个测试位置，例如 `D:\ReportDeskTest\HIS-Copy`。保留查询 XML 和配套模板的相对目录结构。
2. 准备独立备份目录，例如 `D:\ReportDeskBackups`。它不能与所选 HIS 目录相同，也不能互相包含。
3. 在当前电脑打开已受信任的 HTTPS 维护入口，例如 `https://172.18.20.65:8443/admin`。
4. 打开 **报表来源 → 打开本机目录 → 选择目录**，选测试副本，按浏览器提示授权。
5. 点击 **选择备份目录**，选择前述备份目录并授权。然后点击 **使用此目录**。
6. 左侧应显示“本机报表目录”，并列出该目录的报表。原有数据库表单中的未保存输入应保持不变。
7. 在 SQL 编辑器仅增加一行注释，点击 **保存到本机 XML**。用本机文本编辑器重新打开 XML，核对注释和备份文件；不要执行修改后的 SQL。
8. 再通过 XML 编辑器增加 XML 注释并保存，检查文件仍能解析、编码/中文正常、其他文件未变化。
9. 在两个不同电脑或浏览器中选择不同副本。修改 A 副本后，确认 B 副本和服务器公共目录未变化。

目录授权按浏览器、配置文件和网站来源区分。刷新后不会自动启用本机目录，需要点击使用目录；权限失效时点击 **重新授权**。更换协议、IP、端口或清理浏览器数据后可能需要重新选择目录。

## 保存、冲突和恢复

保存顺序：

1. 服务器基于本页私有副本准备并验证候选 XML，返回相对路径和旧/新 SHA-256。
2. 浏览器检查源文件及关联文件仍为原版本；先将全部待改文件备份到独立备份目录并回读校验。
3. 写入本机文件，再逐个回读计算 SHA-256。
4. 全部成功后确认服务器更新私有副本，才允许继续用新版定义查询。

备份按时间和批次保存，保留原相对路径，不自动删除。SQL/XML 文件恢复记录可能暂存在浏览器 IndexedDB；记录含目录句柄、候选 XML 和校验信息，不含查询结果、查询参数值或数据库密码。

多文件写入不是跨文件原子事务。断网、权限失效或部分写入失败时，不要重复点保存：在编辑器中点击 **本机保存状态**，直接进入 **报表来源 → 打开本机目录** 处理。

- **核对并确认保存**：只有全部本机文件为候选新版本时才能确认；刷新后的新页面要求重新扫描，不能沿用旧页面状态。
- **恢复原文件**：先校验整个批次和备份，再恢复已写入的新版本；发现第三方修改时停止，不自动覆盖。
- **核对保存状态**：处理确认响应丢失、仅服务器准备成功等情况。
- 恢复和核对保留编辑器草稿；根据提示复制草稿、关闭编辑器、重新扫描后再编辑。

本机文件被 HIS 或文本编辑器修改后，编辑/查询前的版本检查会阻止继续使用过时文件；需要重新扫描。浏览器不能跨其他应用持有可靠的目录事务锁，建议维护时不要让其他程序同时写入同一组 XML。

## 浏览器与部署条件

| 项目 | 条件 |
| --- | --- |
| 网络入口 | 可信 HTTPS；只有真实本机 loopback 调试允许 HTTP，内网 IP HTTP 不支持目录读写 |
| 浏览器能力 | 安全上下文、`showDirectoryPicker`、Web Crypto、IndexedDB、Web Locks 和可用目录读写权限 |
| Chrome / Edge | 已用本机安装版本执行真实浏览器 OPFS 副本测试；原生 Windows 选目录与权限提示需现场验收 |
| 360 | 用户截图为安全浏览器 15.0.2040.0（32 位），内核 114.0.5735.289；截图页面为极速模式。须在 ReportDesk 页面也启用极速，并执行上述副本验收；版本号不能代替实际接口检测 |
| 服务器 | 现有 .NET Framework 4.6.2 / 4.8 Web 部署；应用池账号需可写既有 DataDirectory |

本次代码不修改 HTTPS 绑定、端口、证书、其他 IIS 站点、数据库 schema 或真实数据。首次上线时只替换本项目文件，不执行整个 IIS 重启。

若浏览器缺少接口，页面会禁用本机目录操作并显示原因；原数据库连接界面保留。普通文件上传不能代替原目录写回，程序不会静默切换为上传后下载。

## 实现位置与边界

- `UI/local-directory.js`：原生目录句柄、原始字节扫描、IndexedDB 恢复记录、Web Locks、备份与回读。
- `UI/web.js` / `web.css`：报表来源窗口内的目录区域、状态及恢复入口；仅服务器兼容模式显示服务器导入页签。
- `UI/transport.js`：本机两阶段保存以及查询/编辑前版本验证。
- `LocalReports.cs` / `BackendAdapter.cs`：会话和标签页私有工作区、分块上传、保存准备与确认。
- `WebRuntime.cs` / `WebOptions.cs`：维护 API、安全来源约束、静态资源和临时目录保护。

服务器临时目录为 `DataDirectory/LocalWorkspaces/<worker>/<workspace>`，不含数据库配置。每个页面按自身最后活动时间独立计时，空闲超过 `IdleMinutes`（默认 60 分钟）后释放；使用另一个标签页不会延长本页寿命。运行中的服务器任务受保护，完成后才重新开始空闲计时。

可见页面的真实鼠标/键盘活动会节流续期；本机物理文件保存期间每 30 秒尽力续期，普通空闲页面没有保活轮询。关闭或离开页面时尽力释放；运行中任务或未决保存拒绝立即释放，之后仍适用空闲规则。关闭通知不保证到达，服务器停机期间也不能清理。已退出 worker 的遗留目录在启动及后台周期检查时依靠专用标记与独占 lease 回收，不删除活动 worker、未知目录或链接；文件占用删除失败后会重试。

临时工作区过期或服务器会话丢失后，页面停止使用本机活动状态，保留编辑草稿与浏览器恢复记录。先核对本机保存状态，再重新扫描加载目录，不自动重复查询或保存。服务器清理不删除电脑上的 XML、独立备份或 IndexedDB 恢复记录；断网和重启不能证明本机文件尚未写入。网站访问权限仍由医院控制。

上传上限：单 XML 32 MiB、每目录 XML 总量 256 MiB、最多 20,000 份 XML；超过时拒绝并提示选择更小的子目录，不截断导入。这些是文件上传容量限制，不是查询时间、查询行数或结果内存截断。

## 升级与回滚

先在测试站点部署候选文件，备份当前站点 `bin` 和 `UI`。保留原 `Web.config`、DataDirectory、TNS、证书以及现有连接配置。旧 Core 兼容包必须与包内说明指定的 Core 哈希一致；不匹配时停止，不强行覆盖依赖。

固定更新包按随包 README 执行检查、更新及同包回滚，不执行整个 IIS 重启。旧站点仍依赖 LIB 时，先保留 LIB 完成升级，验证新版默认本机模式后再自行决定是否移走；回滚到旧版前先恢复原 LIB 与权限。程序更新器不删除、备份或恢复 LIB 内容，也不会跳过旧站点健康门禁。

回滚应用文件不会撤销已经保存到各电脑的 XML；文件回退需使用对应本机备份，并先核对有没有后续修改。默认本机模式不会改写旧服务器报表与同步状态；现有 `Web.config`、数据库连接和多连接列表由更新包按字节保留。

上线及现场权限验收未在本次自动化中执行。目录维护基础验证见 `Verification-Web-LocalDirectory-20261106.md`；默认本机模式及清理验证见 `Verification-Web-LocalXml-20261106.md`，安装边界见 `Web-LocalXml-Update-20261106.md`。
