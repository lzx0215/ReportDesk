# ReportDesk Web 服务器更新包：本机 XML 索引与按需加载

发布：`LocalIndex-20261106-v1`。目标：**.NET Framework 4.6.2 / x64 / 精确旧 Core**。适用于已有 ReportDesk Web 站点的增量更新，不能用来新建站点。本包包含此前设置分区、多数据库连接和报表来源入口功能。

## 本次更新

- 未配置 `ReportDesk.ServerReportsEnabled` 时默认关闭服务器报表目录功能：启动不加载服务器 LIB，不初始化 HIS 发布同步，报表由使用者在浏览器选择本机 XML 目录。
- 已有 `Web.config` 中的 `ReportDesk.ReportsDirectory=C:\LIB` 可以保留。新版默认模式不依赖该目录存在；更新器不改写此项，也不会创建、移动或删除 LIB。
- 需要恢复旧服务器报表功能时，由维护人员明确配置 `ReportDesk.ServerReportsEnabled=true`，并准备有效的服务器报表目录和权限；启用后沿用旧模式的目录检查及同步要求。本更新包不会自动更改配置。
- 数据库连接仍使用原配置，保留多连接、已保存密码及明确切换当前连接的行为。本机报表来源操作不保存或切换数据库连接。

报表目录索引保存在当前浏览器；为匹配 HIS 菜单位置，浏览器会发送查询 XML 的相对路径和内容哈希，位置核对本身不上传 XML 正文。打开报表时将当前报表及解析所需的配套 XML 发送到服务器临时工作区。批量或全部导出 SQL 时，按用户选择的范围临时发送相应查询 XML，导出越多，传输和处理时间越长；完成后释放临时工作区。原始 XML 和独立备份保存在当前电脑；浏览器没有直接连接 Oracle。工作区会按下述规则释放，不应当作持久报表库。

只替换 **`bin/ReportDesk.Web.dll` 和 14 个 `UI` 文件**。不覆盖 Core、其他依赖 DLL、`Web.config`、`Global.asax`、数据目录、TNS 或数据库连接配置，不改数据库。本包不含现场配置、密码或业务 XML。

要求服务器现有 `bin\ReportDesk.Core.dll` 的 SHA-256 精确等于：

```text
6249D398ECC6B39F258AA2BF439BF4ED249576C43170ECE15015953234C7BDA7
```

基线不同会拒绝更新。不要替换 Core 或跳过校验，应按实际 Core 另制匹配包。此前 Settings 和 ReportSources 包及其备份记录保持独立。

## 安装顺序：先更新，再处理原 LIB

**先保留原有 LIB，让旧版本能正常启动并完成本次升级。** 更新器仍要求原站点健康，不绕过首页、`api/session` 或维护门禁。如果旧版本因 LIB 已被移走而不可用，先按原配置恢复该目录及权限，再检查和更新；本包不自动恢复或删除业务文件。

在实际 IIS 服务器上操作，使用 **管理员 Windows PowerShell 5.1**。需要现有 IIS 管理组件。本包不安装组件，不修改系统策略，不调整应用池身份、端口或证书。

1. 完整解压到网站、数据目录和 HIS 目录之外，例如 `D:\ReportDeskUpdate\LocalIndex-20261106-v1`。不要把整包直接覆盖到网站。
2. 右键 **`Check-WebUpdate.cmd` → 以管理员身份运行**，输入 ReportDesk 的实际 IIS 物理路径。该目录应直接包含 `Web.config`、`Global.asax`、`bin` 和 `UI`。成功显示 `CHECK PASSED`、`Status : Checked`、`Exit code: 0`。
3. 通知本应用使用者保存草稿、结束查询后，右键 **`Update-Web.cmd` → 以管理员身份运行**，输入同一路径。记下输出的 **`Backup/recovery directory`**。
4. 成功显示 `UPDATE VERIFIED`、`Status : Updated`、`Exit code: 0`。使用原网址按 **Ctrl+F5** 刷新，确认默认本机 XML 模式、原有数据库连接，并用授权的目录副本验收选择、查询与保存。
5. 确认新版已不依赖服务器 LIB，且该目录未被其他应用使用后，再由维护人员按现场备份安排决定是否移走原 LIB。保留其备份和原路径信息，以便回退旧版本。本包不执行该操作。

如果不能自动识别原访问地址，在解压目录的管理员 PowerShell 中运行（替换两处示例值）：

```powershell
.\Apply-WebUpdate.ps1 -SitePath 'D:\Sites\ReportDesk' -HealthUrl 'https://reportdesk.example.invalid/' -CheckOnly
# 只读检查通过并安排好维护窗口后：
.\Apply-WebUpdate.ps1 -SitePath 'D:\Sites\ReportDesk' -HealthUrl 'https://reportdesk.example.invalid/'
```

URL 必须是本服务器该 IIS 应用的真实地址，子应用要包含子路径；严格校验证书，不绕过证书错误。检查失败时保留原站点，不手动跳过门禁。包内文件哈希不符时重新复制完整 ZIP；Core 不符时停止。

新版运行正常且默认服务器报表功能关闭时，即使旧 ReportsDirectory 不存在，安装器的路径检查也不要求创建它；仍保留路径无链接、站点/数据/备份隔离等校验。此行为不代表依赖 LIB 的旧程序可以在缺少目录时通过健康检查。

## 配置保护与影响

更新器继续使用原 v2 维护门禁：首页及 `api/session` 最多等待 30 秒，必须连续两轮为 HTTP 503 且带本次维护标记，才能替换程序。只读检查不创建维护页或修改配置；HTTP 检查不调用数据库测试或报表 SQL。

安装前备份完整 `bin`、`UI`、站点根 `.config`/`Global.asax` 及 `DataDirectory/config` 的所有文件，包含连接和旧 catalog 配置；安装后核对受保护配置及依赖逐字节不变。默认备份目录为 `%ProgramData%\ReportDesk\WebUpdateBackups\时间-唯一编号`，新建子目录限制为 Administrators/SYSTEM。程序回滚不备份或恢复 LIB 内容。

更新只让本应用短暂进入维护状态和重新加载，现有查询/会话可能中断；不执行 `iisreset`，不停止其他项目，不修改或回收应用池。保持原应用池身份和用户配置文件，已保存密码仍由原身份 DPAPI 解密。**只留在进程内、未保存的临时密码，应用重载后需重新输入。**

更新不主动改写连接文件。网页主动保存连接才记录配置；保存非当前连接不切换。当前连接由同一应用进程内的后续查询使用；多个 IIS worker/实例没有实时切换广播。

本机目录模式沿用原有维护权限边界：每位需要使用本机 XML 的人员必须已有维护端入口权限，普通查询访客不能使用此入口。本机目录模式需要可信 HTTPS 和支持目录读写的浏览器，并由使用者选择及授权目录。索引与目录句柄保存在浏览器；目录权限可能因浏览器重启、清除站点数据或策略限制而需要重新授权，浏览器不支持本机目录读写时不能使用此功能。请先用副本验证。SQL/XML 写回当前电脑前仍需独立备份；这些文件不属于程序回滚范围，保存不等于发布回 HIS。

## 本机临时文件与释放

- 每个页面按 `ReportDesk.IdleMinutes` 独立计算空闲期限，默认 60 分钟；其他页面的操作不会延长它的期限。可见页面中的真实用户操作会节流续期，正在写回本机文件时每 30 秒续期。正在执行的服务器任务不被清理。
- 离开或关闭页面时，浏览器尽力通知服务器释放当前页面。正在运行的任务或尚未确认的本机保存会拒绝立即释放，之后仍按空闲规则处理；不能依赖关闭浏览器的通知一定送达。
- 服务器定期检查 `DataDirectory/LocalWorkspaces` 中已退出 worker 的遗留工作区，只处理程序识别且归属已失效的目录。活动 worker、被占用的工作区和未知目录不删除；删除失败会留待后续重试。
- 清理只处理服务器临时副本，不删除当前电脑的原 XML 或备份，也不自动清除浏览器 IndexedDB 中的保存恢复记录。页面收到会话过期提示后停止使用旧本机会话，保留编辑草稿与恢复记录；重新选择目录并核对保存状态后再继续。

本机保存进行中应保持页面打开。断网、浏览器退出或服务器重载后，先核对本机文件与备份，不能因临时副本已清理就认为文件一定未写入。实际验证以本次包的独立验收记录及现场操作结果为准。

## 回滚与失败处理

**回退到仍依赖服务器 LIB 的旧版本前，先恢复该版本配置中的原 LIB 目录和权限。** 不恢复就可能使旧程序无法启动；即使程序字节恢复，更新器也不能报告健康回滚成功。程序备份不包含 LIB，不能用更新备份替代业务文件备份。

使用**本包**的 **`Rollback-WebUpdate.cmd`**，输入本次 LocalIndex 更新的备份目录和原站点路径；或以管理员运行：

```powershell
.\Apply-WebUpdate.ps1 -SitePath 'D:\Sites\ReportDesk' -Rollback -BackupDirectory 'C:\ProgramData\ReportDesk\WebUpdateBackups\本次完整备份目录'
```

成功显示 `ROLLBACK VERIFIED`、`Status : RolledBack`。不得交叉使用其他发布包与本次备份。升级后如果保存了新的连接配置，自动回滚检测到变化会拒绝覆盖；保留当前配置和原备份，先核对差异，再安排程序回退。更早、不支持多连接的旧版本若保存配置，会丢失附加列表，因此先另备份最新 `connection.json`。

`RECOVERY REQUIRED`、维护门禁失败或中途断电时，保留完整备份目录和 `journal.json`，不要盲删维护页、强制覆盖程序或配置。核对原 LIB、路径、权限及备份后，用同一包继续恢复；脚本不删除归属不明的维护文件。
