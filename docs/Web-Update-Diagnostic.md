# ReportDesk 更新前只读诊断

用于排查：站点配置指向 `C:\ReportDeskData`，但服务器找不到该目录，同时原网页仍可打开、连接信息仍显示。

这不是更新包，也不是自动修复工具。它不创建 `C:\ReportDeskData`，不修改网站/数据库配置，不启停 IIS 或应用池，不访问网页接口或 Oracle。只在执行账号的临时目录生成两份相同内容的诊断结果（TXT 和 JSON）。

## 操作

1. 将此 ZIP 复制到 IIS 服务器，完整解压到桌面等网站目录之外的位置。
2. 右键 **`Diagnose-WebUpdate.cmd` → 以管理员身份运行**。当前默认网站目录已经填写为用户确认的 `C:\a_userspace\ReportTool\ReportDesk-Web`，不需要重复输入。
3. 等待扫描完成。脚本会显示结果文件的完整路径，并打开记事本。
4. 把记事本中的诊断结果发回。诊断只输出目录、DLL 哈希、IIS 元数据、候选文件路径及检查状态，不输出数据库账号密码或连接 JSON 内容。

窗口保持在结束提示，避免闪退；失败时可截取窗口的状态。无需先关闭正在运行的网站。

## 诊断内容

- 直接读取指定网站 `Web.config` 中两个目录设置及它们的存在/访问状态。
- 读取 `ReportDesk.Web.dll` 与 `ReportDesk.Core.dll` 的 SHA-256，不执行这些 DLL。
- 通过 IIS 管理接口只读查询匹配的站点/应用、绑定、池身份类型、LoadUserProfile、32 位设置、worker PID/启动时间，以及两个有效目录配置；失败时保留“未知/无法读取”，不假设默认值。
- 包含隐藏文件地查找 `connection.json`、`catalog.json`，只记录文件路径、大小和修改时间，不读取文件内容。
- 默认候选范围：部署目录的上级、配置中的数据目录、ProgramData 下的 ReportDesk、各用户及系统账号已知的 ReportDesk 子目录，以及固定磁盘根目录名称包含 ReportDesk/ReportTool 的文件夹。不会扫描整个 Users/AppData，也不会全盘递归。

候选搜索不跟随链接/联接目录，深度最多 8 层，最多 5,000 个目录、100,000 个目录条目。30 秒预算在目录操作之间检查，单个 Windows 文件操作阻塞时可能超过该时间。报告会标出截断、跳过路径和读取错误；无结果只代表本次可检查范围内没有找到。

用户目录或备份里的匹配文件只是候选，不代表当前网站正在使用它。IIS 查询显示的是当前配置，不能证明运行进程内存中已经加载了相同值。不要根据文件最新时间直接覆盖或迁移配置。

## 可选命令

站点路径不同才需要在管理员 Windows PowerShell 中指定：

```powershell
.\Diagnose-WebUpdate.ps1 -SitePath '实际网页程序目录'
```

诊断代码未部署到医院服务器；真实 IIS 读取仍须现场执行确认。原一键更新包保持不变，先定位连接配置再继续更新。
